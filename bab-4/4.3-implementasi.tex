\section{Implementasi}
\label{sec:implementasi}

Tahap implementasi merupakan proses penerjemahan rancangan arsitektur dan kebutuhan fungsional ke dalam kode program yang berjalan. Pengembangan sistem MonPD Reborn dilakukan dengan menggunakan framework ASP.NET Core MVC dan bahasa pemrograman C\#. Penulis berperan penuh dalam pembangunan Application Layer (back-end) dan Presentation Layer (front-end) untuk memastikan sistem dapat mengolah data perpajakan dari database Oracle secara efisien.

Sistem MonPD Reborn dirancang untuk meminimalkan waktu tunggu pengguna melalui mekanisme pemuatan data asinkron. Berbeda dengan sistem lama yang memuat seluruh data secara sekaligus, alur kerja sistem ini dibagi menjadi beberapa tahapan sebagai berikut:
\begin{enumerate}
    \item \textbf{Pemuatan Kerangka (Initial Load)}: Saat pengguna mengakses menu, browser hanya memuat struktur HTML dasar (Razor View) tanpa data. Hal ini membuat halaman terasa instan saat dibuka.
    \item \textbf{Permintaan Data (AJAX Request)}: Setelah kerangka siap, fungsi JavaScript (jQuery) secara otomatis mengirimkan permintaan ke Action Method di Controller di latar belakang.
    \item \textbf{Pengolahan Data (Back-end Processing)}: Controller memanggil method di dalam ViewModel untuk berinteraksi dengan database Oracle melalui Entity Framework Core.
    \item \textbf{Pengembalian Hasil (Response)}: Server mengembalikan data dalam format Partial View atau JSON.
    \item \textbf{Perenderaan Dinamis (Client-side Rendering)}: Komponen DevExtreme DataGrid menerima data tersebut dan menampilkannya kepada pengguna tanpa perlu melakukan penyegaran halaman (refresh).
\end{enumerate}

Mekanisme ini memungkinkan halaman terasa instan saat dibuka karena \emph{browser} tidak perlu menunggu seluruh data dari \emph{database} Oracle selesai ditarik sebelum menampilkan antarmuka.

\subsection{Pengembangan Application Layer (Backend)}
Penulis menerapkan pola arsitektur Fat ViewModel dan Thin Controller. Pendekatan ini bertujuan untuk memusatkan seluruh logika bisnis, pemfilteran, dan agregasi data di dalam ViewModel, sehingga Controller tetap ramping dan hanya berfungsi sebagai pengatur alur permintaan.
\begin{enumerate}
    \item Struktur ViewModel: Setiap modul memiliki ViewModel khusus, seperti ReklameLiarVM. Di dalamnya terdapat berbagai kelas seperti Index, Show, dan Detail untuk melayani kebutuhan data yang spesifik.
    \item Logika Pengambilan Data: Penulis membangun method seperti GetDataRekapWPList() untuk menangani filter dinamis dan memanggil Stored Procedure yang disediakan oleh tim database Bapenda.
    \item Enkapsulasi Logika: Seluruh kalkulasi persentase pencapaian dan perbandingan target vs realisasi dilakukan di sisi server sebelum dikirim ke front-end untuk menjaga konsistensi data.
\end{enumerate}

\subsection{Pengembangan \emph{Presentation Layer} (\emph{Frontend})}
Pada lapisan presentasi, penulis fokus pada pembangunan antarmuka yang responsif dan interaktif menggunakan jQuery dan toolkit DevExtreme.
\begin{enumerate}
    \item \textbf{Implementasi AJAX:} Penulis menulis fungsi \emph{JavaScript} seperti \texttt{fnShow()} untuk memicu pemuatan tabel secara asinkron. Teknik ini berhasil mereduksi waktu muat dari $\pm 120$ detik menjadi hanya $\pm 3 - 5$ detik.
    \item \textbf{Konfigurasi \emph{DevExtreme DataGrid}:} Komponen ini dikonfigurasi untuk menangani volume data besar dengan fitur \emph{server-side paging}. Penulis juga mengimplementasikan \emph{Banded Columns} untuk mengelompokkan data yang berkaitan, seperti kolom ``Pokok'' dan ``Sanksi'' di bawah kategori tahun yang sama.
    \item \textbf{Fitur \emph{Drill-down}:} Melalui fungsi \texttt{showDetailModal()}, pengguna dapat mengklik angka pada tabel rekapitulasi untuk menampilkan \emph{pop-up} detail transaksi individual yang dimuat melalui \emph{Partial View} \texttt{\_Detail.cshtml}.
\end{enumerate}
